# RTX 4060 Laptop 实测：CPU 暂存复制与暖缓存管线等待

**社区接力最值得追的是哪一笔绘制在等管线。** 四轮实机测试发现，一块 20.07 MiB 缓冲的内容连续多次与 CPU 暂存相同，比较两份内存却仍需约 3 ms。暖缓存下还有两组候选着色器，游戏首次绑定与宿主就绪日志相隔约 0.9 秒，两段跨度内均有两次呈现。要判断预热影响的是帧率还是缺失的绘制，需要将首次需求、实际绘制和呈现连起来。[四轮计数与管线事件](2026-11-27-warm-pso.json)

## CPU 复制少做了多少

定位轮在 240 个呈现间隔中观察到 254 个包含指定 32 KiB 纹理的准备组。其中 194 组最后完成的是同一块 21,045,760 字节缓冲的全量 CPU 复制。它在其他任务都结束后仍占用的时间合计 543.95 ms。固定其他任务的完成时刻，单独消去这些尾段的乐观上限是 **2.27 ms/帧**，该窗实测为 **7.90 FPS**，按这个上限推算可达约 **8.04 FPS**。

随后用同一诊断构建跑四个独立进程。A 沿用全量复制，B 在同类准备组内比较原数据和暂存，只写变化块。两侧都继续登记整段待上传范围，沿用 GPU 上传和同步。使用同一存档、暖缓存、按键路线，Series S 配置，1920×1080 宿主输出，接电并开启应用保频。四轮在启动后第 16、24、32 秒各按住 Enter 0.8 秒，从同一类热缓冲首次绑定后选取连续 240 个间隔。公开数据可复算这些窗口，精确复现实机路线还需要当时的存档。此开关属于实验构建，本次发布的是测量结果。[构建标识、路线与样本口径](2026-11-27-warm-pso.json)

| 运行顺序 | 目标操作次数 | 单次操作 P50 / P99（ms） | 全窗 Present P50 / P99（ms） | 全窗 FPS |
|---|---:|---:|---:|---:|
| B1 比较后写 | 203 | 2.77 / 7.32 | 89.45 / 577.41 | 8.16 |
| A1 全量复制 | 121 | 2.63 / 4.95 | 114.45 / 596.56 | 6.81 |
| A2 全量复制 | 156 | 2.60 / 4.93 | 133.28 / 620.38 | 6.22 |
| B2 比较后写 | 180 | 2.99 / 6.82 | 123.04 / 664.06 | 6.45 |

B 的 **383/383 次**比较覆盖 7.507 GiB 的逻辑缓冲范围，写进 CPU 暂存的字节为 **0**；380 次仍在组内最后完成。固定输入回放每种输入每臂 24 次，内容相同、稀疏变化、真实派发前后变化三种情况下，B 的单次中位耗时分别少 0.486、0.359、0.190 ms，CPU 输出逐字节一致。游戏实测将各次调用合并后，A 的 P50 为 2.607 ms，B 为 2.912 ms。四个跨臂组合在绘制、派发和提交次数上均匹配 **0 对活动帧**。同负载 Direct 提前量、慢帧 P50/P99 收益及呈现画面的逐像素一致性仍未知。[960 个呈现间隔及工作量](2026-11-27-present-arms.json)

在仓库根目录运行以下 PowerShell 命令可复算四轮 FPS。逐帧数据每行依次为两个宿主呈现标记之间的计时器刻度，以及期间的绘制、派发、提交次数。四轮表格的 P50/P99 均对排序后的帧时间做线性插值。

```powershell
$sample = Get-Content docs/benchmarks/2026-11-27-present-arms.json -Raw | ConvertFrom-Json
foreach ($arm in $sample.arms.PSObject.Properties) {
    $ticks = ($arm.Value | ForEach-Object { $_[0] } | Measure-Object -Sum).Sum
    [pscustomobject]@{ Run = $arm.Name; FPS = [math]::Round($arm.Value.Count * $sample.qpc_hz / $ticks, 2) }
}
```

## 暖缓存仍在等什么

着色器预编译和驱动管线预热分别处理不同工作。针对一批真实计算负载，离线生成 19 个着色器的 DXIL 共用 525.61 ms，19/19 与暖缓存逐字节一致。一次独立运行中，热点计算着色器对应的宿主管线在首次观测到的热绑定前 3.81 秒已经就绪。驱动执行绘制还需要管线状态对象（PSO），其中包含着色器、根签名和渲染状态。定位轮实际载入 102.52 MiB 管线库，一次保存时累计载入 1,833 个 PSO、新建 31 个、提前启动 1,829 项。这些计数的阶段有重叠。[管线库与预热名单实现](../../crates/victory-gpu/src/pipeline/library.rs)

实测后端是 D3D12，生成的 Shader Model 6.6 着色器已经用索引访问资源和采样器堆（Bindless）。本机 Vulkan 驱动上报 1.4.303，支持动态渲染、描述符索引和图形管线库。现有测量仅验证 Vulkan 功能可用，游戏帧时来自 D3D12。[着色器资源访问](../../crates/victory-shader/src/emit/mod.rs#L17)

四轮 960 个间隔中，完整落入热窗的 24 个引擎统计段共报告 908 帧。按段内帧数加权，B1、A1、A2、B2 的录制线程管线等待分别为 **13.38、15.53、0.27、6.67 ms/帧**。A1 的峰值段持续 5.737 秒，共 33 帧，约 1,462 线程·毫秒，折合 **44.3 ms/帧**。多个录制线程可同时等候。该段有 47 个首次绑定的游戏管线对象、81 条分着色阶段的首次绑定日志，并有 3 条宿主 mesh 管线就绪日志。[分段数据和八个选样事件](2026-11-27-warm-pso.json)

## 下一项最小实验

1. **找同一条管线。** 对上述候选同时记录客体预热键、宿主完整状态键和运行内实例标识。用同一 QPC 时钟记录预热入队、首次真实需求、后台取工、取得库锁、驱动 Load/Create 返回及结果发布。库按名称哈希分到 64 把锁，mesh 路径经过流式 `LoadPipeline`。时间戳与返回码能区分取锁、库命中和创建。[库锁](../../crates/victory-gpu/src/pipeline/library.rs#L422) · [mesh 管线入口](../../crates/victory-gpu/src/pipeline/host.rs#L949)
2. **找等它的绘制。** 将成功、编译失败和等到预算耗尽的绘制分别计数。记录命令列表、重置代次和客体提交，再配到原生 Direct、对应 Present 的入口与返回。宿主会复用已绑定的状态，必须记录实际 Draw、Dispatch 或间接命令。[等待预算](../../crates/victory-gpu/src/pipeline/make.rs#L276) · [绑定复用](../../crates/victory-gpu/src/draw.rs#L1633)
3. **只提前准备一个已证实挡住提交的 PSO。** 从共同路线锚点比较 CPU 少等、Direct 提前、Present 提前各多少毫秒，另记成功绘制、跳过绘制和像素变化。提前准备若使原先被跳过的绘制恢复，单列画面完整性收益。两组候选各自影响多少整帧时间，仍待实测。
